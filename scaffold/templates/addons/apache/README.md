# Apache add-on

The add-on owns three standard source files under `addons/apache/conf/`. During
scaffold initialization they become normal, editable application files:

- `conf/apache/00-logs.conf`;
- `conf/apache/01-reverse-proxy.conf`;
- `conf/apache/02-server-status.conf`.

The scaffold does not compile Apache routes or virtual hosts. Developers edit
`conf/apache/01-reverse-proxy.conf` directly so single- and multi-application
routing remains visible in the application repository. Use the prefixed service
variables generated by the installer, such as `API_APP_PORT`, `WEB_APP_PORT`,
or `API_INSTALL_PATH`, wherever deployment values are required.

## Default application versus multiple applications

`ADDONS.apache.CONFIG_SERVICE` selects the application used by the baseline
catch-all route. The installer exposes these convenience values:

- `INSTALL_PATH`: selected service's `INSTALL_PATH`;
- `APACHE_UPSTREAM_SERVICE`: selected Compose service name;
- `APACHE_UPSTREAM_PORT`: selected service's `APP_PORT`;
- `APACHE_PROXY_TIMEOUT`: selected service's `GUNICORN_TIMEOUT`;
- `APACHE_LOG_STEM`: filename-safe form of `APACHE_SERVER_NAME`.

The unprefixed `INSTALL_PATH` is a short alias for the default service and is
not configured separately. Application-owned values are generated with their
service prefix. For services named `api` and `web`, use
`API_INSTALL_PATH`, `API_APP_PORT`, `WEB_INSTALL_PATH`, and `WEB_APP_PORT`—not
duplicated names such as `APACHE_API_INSTALL_PATH`.

For example, two Django services exposed under path prefixes can use:

```apache
# Exclusions must appear before the catch-all ProxyPass rules.
ProxyPass /api/static/ !
Alias /api/static/ "${API_INSTALL_PATH}/static/"
<Directory "${API_INSTALL_PATH}/static">
    Require all granted
</Directory>
ProxyPass /api/documents/ !
Alias /api/documents/ "${API_INSTALL_PATH}/documents/"
<Directory "${API_INSTALL_PATH}/documents">
    Require all granted
</Directory>
ProxyPass /api/ http://api:${API_APP_PORT}/
ProxyPassReverse /api/ http://api:${API_APP_PORT}/

ProxyPass /analysis/static/ !
Alias /analysis/static/ "${ANALYSIS_INSTALL_PATH}/static/"
<Directory "${ANALYSIS_INSTALL_PATH}/static">
    Require all granted
</Directory>
ProxyPass /analysis/ http://analysis:${ANALYSIS_APP_PORT}/
ProxyPassReverse /analysis/ http://analysis:${ANALYSIS_APP_PORT}/
```

A React service keeps its compiled assets inside its own Nginx container, so
Apache normally proxies it rather than adding an `Alias`:

```apache
ProxyPass /web/ http://web:${WEB_APP_PORT}/
ProxyPassReverse /web/ http://web:${WEB_APP_PORT}/
```

The `${...}` tokens above are resolved from the generated Compose environment
when `container_install.sh` renders the application-owned Apache source files.

`container_install.sh` loads the selected production or test settings, renders
every shell-style uppercase variable in those source files, and writes the
completed bind sources under `deployment/apache/`. Compose mounts only the
completed files. Rerunning the installer regenerates them from the editable
sources, so configuration changes are repeatable.

Apache does not own another installation-settings file. Its `APACHE_*` and
`SERVER_STATUS_*` section is appended to one selected application service's
normal production/test settings. For a standalone project the only service is
selected automatically. A multi-app project selects the owner explicitly:

```json
"apache": {
  "CONFIG_SERVICE": "web",
  "MOUNTS": [
    "reports_data:/var/www/reports:ro,z"
  ]
}
```

The generic add-on Compose compiler provides:

- dependency health ordering;
- a TCP health check and configurable host port;
- a persistent production log bind and disposable test log volume;
- profile-owned static/document mounts where an integration fragment exists;
- optional application mounts from `ADDONS.apache.MOUNTS`.

The source configuration directory, rendered configuration directory, and log
bind have an independent Apache host-permission specification. Apache has an
explicit empty running-container mount specification because it owns no
writable named volume.
