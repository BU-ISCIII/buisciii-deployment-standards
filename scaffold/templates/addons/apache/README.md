# Apache add-on

The add-on owns three standard source files under `addons/apache/conf/`. During
scaffold initialization they become normal, editable application files:

- `conf/apache/00-logs.conf`;
- `conf/apache/01-reverse-proxy.conf`;
- `conf/apache/02-server-status.conf`.

The scaffold does not compile Apache routes or virtual hosts. Developers edit
`conf/apache/01-reverse-proxy.conf` directly so single- and multi-application
routing remains visible in the application repository. Use the prefixed service
variables generated by the installer, such as `API_APP_PORT`, `WEB_APP_PORT`,
or `API_INSTALL_PATH`, wherever deployment values are required.

`container_install.sh` loads the selected production or test settings, renders
every shell-style uppercase variable in those source files, and writes the
completed bind sources under `deployment/apache/`. Compose mounts only the
completed files. Rerunning the installer regenerates them from the editable
sources, so configuration changes are repeatable.

Apache does not own another installation-settings file. Its `APACHE_*` and
`SERVER_STATUS_*` section is appended to one selected application service's
normal production/test settings. For a standalone project the only service is
selected automatically. A multi-app project selects the owner explicitly:

```json
"apache": {
  "CONFIG_SERVICE": "web",
  "MOUNTS": [
    "reports_data:/var/www/reports:ro,z"
  ]
}
```

The generic add-on Compose compiler provides:

- dependency health ordering;
- a TCP health check and configurable host port;
- a persistent production log bind and disposable test log volume;
- profile-owned static/document mounts where an integration fragment exists;
- optional application mounts from `ADDONS.apache.MOUNTS`.

The source configuration directory, rendered configuration directory, and log
bind have an independent Apache host-permission specification. Apache has an
explicit empty running-container mount specification because it owns no
writable named volume.
